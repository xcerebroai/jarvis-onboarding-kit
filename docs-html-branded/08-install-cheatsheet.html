PHASE 0

Before You Touch the Machine

  • Intake form reviewed; buy box in writing
  • Decide whose Anthropic Console account/card (default: the client's)
  • KB template files ready, placeholders filled — 02_buy-box.md must have real numbers
  • Channels decided: Telegram (default) / WhatsApp (dedicated number only)
  • Client at the machine — they type all passwords; we never receive credentials
PHASE 1

Prerequisites

MacCmd+Space → “terminal” → Enter  ·  WindowsStart → “powershell” → Enter

Check what exists:

node --version        # need v18+
python3 --version     # Mac        |        python --version   # Windows — need 3.10+
  • Node missing → nodejs.org → LTS installer, defaults (Apple Silicon vs Intel: Apple menu → About This Mac)
  • Python missing (Windows) → python.org installer → ✅ tick “Add Python to PATH” on the first screen
  • Mac: “command line developer tools” popup → click Install (brings Git, 5–15 min). No popup? xcode-select --install
  • Windows: don't hand-install Git — the Hermes installer pulls it

Network pre-flight (60 seconds, saves an hour):

curl -I https://api.telegram.org

HTTP response → clear. Hangs / redirect → network blocks Telegram: plan hotspot NOW, permanent fix later (see Troubleshooting).

⚠️
RULE: after ANY install, close the shell completely and open a FRESH one. New commands aren't visible to old sessions — this causes half of all fake “it didn't install” panics.
PHASE 2

Install Hermes

  1. Run the standard Hermes installer — let it finish untouched (the “11 steps” phase may stall waiting for the Mac developer-tools popup: click Install on it)
  2. Fresh shell, then:
hermes --version
  • Note the version in the tracker — 0.18+ = flashing-window bug fixed upstream; 0.17 on Windows may need the local patch later
  1. First run:
hermes gateway

Its complaints = your to-do list. “Provider not configured” is normal on a virgin install.

PHASE 3

Connect Claude — the landmine field

Nothing installs for Claude — it's a key, not a program.

In the browser (client drives): 1. console.anthropic.com → sign up with the CLIENT's email (separate from claude.ai chat — a chat subscription does NOT include API) 2. Billing → add card → buy starter credits ($5–25)

  • SET MONTHLY SPEND LIMIT NOW (Settings → Limits) — before the first key exists
  1. API Keys → Create Key → name it → copy with the Copy button (drag-select = stray spaces)

In Hermes:

  1. Click “I have an API key” (bottom of the provider screen)
⛔
NEVER click “Sign in with Anthropic OAuth” or run claude setup-token — that path bills the wrong bucket silently. Cancel any popup that mentions OAuth.
  • VERIFY THE SLOT: key lands in the Anthropic row · OpenRouter row EMPTY · active dot on Anthropic (the dialog has dropped keys into OpenRouter before — check every time)
  • PIN THE MODEL: Sonnet (highest Sonnet number). Opus ≈ 5× the cost on routine traffic
  • Gateway status reads ready

Error decoder

Bot / gateway says Meaning Fix
Provider authentication failed Key in wrong slot or bad paste OpenRouter row empty; re-paste with Copy button
No usable credit Account unfunded OR key from another account Key + money + account = same house; buy credits
Error mentions “OpenRouter” OpenRouter still the active provider TRASH the OpenRouter entry (not just clear the text), select Anthropic, restart
PHASE 4

Telegram

Create the bot (client's phone): 1. Search @BotFather (verified check) → /newbot 2. Display name = client's brand · username must end in bot 3. Copy the bot token → client saves it in their password manager (never in screenshots or group chats) 4. Client taps START on the new bot — a bot can't speak first

Get the numeric user ID (not the @username): - @userinfobot — the EXACT handle, verified badge; search results are full of scam clones - Bulletproof fallback: client messages their own bot, then open https://api.telegram.org/bot<TOKEN>/getUpdates → find "from":{"id": → that number - Lost the bot later? BotFather → /mybots → tap the bot → tap its @username

Wire it — Hermes → Messaging → Telegram:

  • Bot token pasted
  • Numeric user ID in Allowed Telegram user IDs (comma-separate multiple people)
  • Allow all users = false/empty. Always. An open bot is anyone burning the client's API money
  • Home channel ID = same user ID (lets the agent initiate: crons, alerts)
  • Save changes

Round-trip test: client's phone → bot → “confirm you're connected”

💡
The sender must not be the account the agent is linked to (the WhatsApp lesson: you can't message yourself). Silent bot + “Connected” status = allowlist miss.
PHASE 5

Knowledge Base

  1. Create the folder — Mac~/Documents/JARVIS-Knowledge · WindowsDocuments\JARVIS-Knowledge
  2. Drop in the filled template set: _INDEX.md, 00–09, plus 10_jarvis-crm-rules.md
  3. Load + persist — send to the agent:

Read every file in [folder path], starting with _INDEX.md. These are your permanent knowledge base — your source of truth. Add a permanent instruction to your memory: at the start of every session, on any channel, read this folder before business tasks. Then prove it: summarize the operating doctrine in 3 bullets and state my buy box.

  • Buy box comes back with the CLIENT's real numbers — a generic answer means the files weren't found or placeholders were never filled

Convention: business doctrine in the root; machine/technical notes in an ops\ subfolder.

PHASE 6

Jarvis CRM Connection

  1. Client's sub-account → Settings → Private Integrations → create token. Scopes: contacts R/W, opportunities, tags, notes, tasks — nothing more
  2. Store the token the agent's secure-config way — ask the agent itself: “What's the secure way to store credentials in your config, without a plain knowledge file?” Never paste tokens into KB files
  • AUTOMATION REVIEW FIRST: which tags/stages/forms fire campaigns in this sub-account → fill the DANGER LIST in files 06 + 10 (this is the 231-duplicate-texts insurance)
  1. Deploy 10_jarvis-crm-rules.md, agent confirms. Core rules it enforces: tags via additive POST /contacts/{id}/tags ONLY — never in an upsert body · browser-style User-Agent on all requests · no invented values · approval before real-contact writes · no blind retries on errors
  2. Connection test — agent creates the standard test contact (Hermes Test · 123 Test Property St · tag “Install Test” · stage New Lead) and reads it back with ID, tags, stage
  • Human check in the CRM: contact right · tags right · nothing fired
PHASE 7

Make It Survive Reboots

  • Windowshermes gateway install — run PowerShell as Administrator (without admin it silently falls back to a flimsy Startup-folder VBS)
  • Maccheck hermes gateway --help for the service/install option
  • Reboot test if time allows: restart machine → bot answers without anyone opening the app
PHASE 8

Acceptance — all must pass

  • Bot answers on Telegram from the client's phone
  • “What AI model are you using?” → names Sonnet
  • “What is my buy box?” → the client's real numbers
  • Console Usage page shows today's traffic — proves billing is on the key + spend limit; the check that catches wrong-path billing on day one
  • Test contact verified in CRM, zero automations fired
  • Client sends a prompt with their own hands
  • Handoff playbook delivered · Day-7 follow-up booked · tracker filed

Standing Rules — every install, no exceptions

  1. OAuth for Claude: never. API-key path only
  2. Key slot: Anthropic row, verified visually, every time
  3. Spend limit before first key
  4. Sonnet pinned, not Opus
  5. Allowlists locked; allow-all false
  6. WhatsApp = dedicated number only — never a personal line (the ban risk lands on the human)
  7. No testing on real contacts. Ever
  8. Agent ground rules in doctrine: no fabricated numbers · report-before-fix · if a safety guard blocks an action, surface it — never restructure around it
  9. Client types their own passwords. We store none
  10. Client-facing = JARVIS. Hermes/GHL are internal words

Troubleshooting Quick-Draw

“command not found” right after installing → Fresh shell. (Windows delete syntax: Remove-Item path -Force, not rm -f.)
Telegram stuck at “attempt 1/8” + DNS-over-HTTPS hunting → Network blocks Telegram. Ladder: hotspot test (2 min, confirms it) → DNS swap to 1.1.1.1 / 8.8.8.8 (Mac: System Settings → Wi-Fi → Details → DNS) → router parental-controls whitelist for api.telegram.org → dedicated data SIM or paid auto-connect VPN (last resort — VPNs fail silently). US home ISPs almost never block: look for a VPN on the machine or a missed macOS “allow incoming connections?” popup first.
Bot connected but silent → Allowlist: numeric ID (not @username) · saved · sender isn't the account the agent is linked to.
Gateway weirdness after repeated launches (Windows) → Task Manager → Details → end ALL hermes/python/node processes → launch ONCE → wait 30s. Stacked instances = event-loop stalls, ghost states.
UI shows stale status after you fixed it → Full quit (system tray too) → reopen. The terminal log is the truth; the UI lags.
Flashing node.exe windows (Windows, WhatsApp bridge) → v0.17 bug — bridge respawns with a visible console; closing the window kills it and loops. 0.18+ fixed upstream. On 0.17: hidden-window patch + crash-loop alert (see Dark Phoenix ops notes).
Any fix on a live agent → Report-only diagnosis → backups + rollback command in hand → then change. Never let the agent kill the gateway it's running through.
